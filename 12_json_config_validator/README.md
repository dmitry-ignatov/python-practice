# 12 JSON Config Validator

Консольная программа для проверки структуры, типов данных и значений в JSON-конфигурации на Python.

Проект сделан для закрепления работы с JSON, `pathlib`, разделения валидации на функции и автоматического тестирования через `pytest`.

Программа читает файл `config.json`, выводит его содержимое и сообщает об отсутствующих полях, неправильных типах данных и недопустимых значениях.

## Формат конфигурации

Программа ожидает JSON-объект следующего вида:

```json
{
    "app_name": "Task Manager",
    "debug": true,
    "max_users": 100,
    "log_level": "INFO"
}
```

Верхний уровень JSON должен быть объектом, который после загрузки в Python становится словарём `dict`.

## Правила проверки

### `app_name`

* обязательное поле;
* тип данных — `str`;
* строка не должна быть пустой или состоять только из пробелов.

### `debug`

* обязательное поле;
* тип данных — `bool`.

### `max_users`

* обязательное поле;
* тип данных — строго `int`;
* значение `bool` не принимается как целое число;
* число должно быть больше нуля.

### `log_level`

* обязательное поле;
* тип данных — `str`;
* допустимые значения:

```text
DEBUG
INFO
WARNING
ERROR
CRITICAL
```

## Возможности

* чтение `config.json` в кодировке UTF-8;
* проверка, что содержимое JSON является словарём;
* поиск отсутствующих обязательных полей;
* проверка типов данных каждого поля;
* проверка допустимых значений;
* разделение ошибок на три категории;
* вывод содержимого конфигурации;
* вывод понятных сообщений об ошибках;
* обработка отсутствующего файла;
* обработка некорректного формата JSON;
* структура программы через отдельные функции;
* запуск через `main()` и `if __name__ == "__main__"`;
* автоматические тесты через `pytest`.

## Категории ошибок

Программа отдельно показывает:

```text
В JSON файле отсутствуют поля
В JSON файле неправильный тип данных у
В JSON файле некорректные значения в
```

Поле с отсутствующим значением или неправильным типом не передаётся в следующую проверку, которая могла бы вызвать ошибку при сравнении или вызове строкового метода.

## Обработка ошибок файла

Если файл `config.json` не найден, программа выводит:

```text
Файл JSON не найден
```

Если содержимое файла нельзя разобрать как JSON:

```text
Некорректный формат JSON
```

Если верхний уровень JSON не является объектом:

```text
Содержимое JSON не является словарем
```

## Пример работы

Для корректной конфигурации:

```text
app_name: Task Manager
debug: True
max_users: 100
log_level: INFO
```

Пример конфигурации с ошибками:

```json
{
    "app_name": "Task Manager",
    "debug": "yes",
    "max_users": 0
}
```

Результат:

```text
app_name: Task Manager
debug: yes
max_users: 0
В JSON файле отсутствуют поля:
'log_level'

В JSON файле неправильный тип данных у:
'debug'

В JSON файле некорректные значения в:
'max_users'
```

## Как запустить

Перейти в папку проекта:

```bash
cd 12_json_config_validator
```

Запустить программу:

```bash
python json_config_validator.py
```

Файл `config.json` должен находиться в папке проекта рядом с `json_config_validator.py`.

## Автоматические тесты

Для запуска тестов нужен `pytest`:

```bash
python -m pip install pytest
```

Запускать тесты нужно из корня проекта:

```bash
python -m pytest
```

Проект содержит 25 тестовых сценариев. Они проверяют:

* возвращаемые значения функций;
* положительные, отрицательные и пограничные случаи;
* чтение корректного JSON;
* отсутствующий файл и повреждённый JSON;
* текст, напечатанный программой;
* все основные ветки функции `main()`.

В тестах используются:

* `assert`;
* `@pytest.mark.parametrize`;
* собственная фикстура `@pytest.fixture`;
* встроенные фикстуры `tmp_path`, `capsys` и `monkeypatch`.

`tmp_path` позволяет создавать временные файлы, `capsys` — проверять вывод через `print()`, а `monkeypatch` — временно заменять `get_json()` при отдельном тестировании `main()`.

## Статус проекта

Проект завершён как учебный мини-проект для закрепления `json.load()`, `pathlib`, проверки структуры и типов данных, последовательной валидации, обработки `FileNotFoundError` и `json.JSONDecodeError`, а также автоматического тестирования через `pytest`.
