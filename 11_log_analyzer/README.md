# 11 Log Analyzer

Консольная программа для анализа файлов журналов и создания отчёта на Python.

Проект сделан для закрепления разбора структурированных строк, работы с датами и временем, фильтрации записей, подсчёта повторений через `Counter`, работы с файлами и обработки ошибок.

Программа принимает путь к `.log`-файлу, разбирает корректные записи, учитывает повреждённые строки и позволяет работать с результатом через консольное меню.

## Формат строки лога

Программа ожидает записи следующего вида:

```text
2026-07-18 14:32:10 | ERROR | Не удалось подключиться к базе данных
```

Строка разделяется на три части:

```text
дата и время | уровень | сообщение
```

Дата и время должны соответствовать формату:

```text
ГГГГ-ММ-ДД ЧЧ:ММ:СС
```

Для разбора даты используется `datetime.strptime()`.

## Возможности

* ввод пути к лог-файлу через консоль;
* удаление лишних пробелов вокруг введённого пути;
* проверка существования пути;
* проверка, что путь ведёт именно к файлу;
* разрешение только файлов формата `.log` без учёта регистра;
* чтение файла в кодировке UTF-8;
* разделение строки на дату и время, уровень и сообщение;
* преобразование даты и времени в объект `datetime`;
* проверка формата и существования даты;
* подсчёт корректных и повреждённых строк;
* поиск записей по уровню `INFO`, `WARNING`, `ERROR` или `DEBUG`;
* поиск текста внутри сообщения без учёта регистра;
* поиск всех записей за выбранную дату;
* подсчёт записей уровней `INFO`, `WARNING` и `ERROR`;
* поиск до трёх самых частых сообщений уровня `ERROR`;
* вывод количества повторений каждой частой ошибки;
* работа через консольное меню;
* сохранение отчёта рядом с исходным логом;
* обработка ошибок кодировки, чтения, доступа и сохранения;
* структура программы через функции;
* запуск через `main()` и `if __name__ == "__main__"`.

## Повреждённые строки

Строка считается повреждённой, если:

* её нельзя разделить на дату и время, уровень и сообщение;
* дата и время не соответствуют формату;
* дата или время содержат невозможное значение.

Например:

```text
повреждённая строка
2026-13-18 14:32:10 | ERROR | Некорректный месяц
2026-02-30 14:32:10 | WARNING | Несуществующая дата
```

Повреждённые строки учитываются отдельно и не участвуют в поиске, статистике уровней и подсчёте частых ошибок.

## Меню

После чтения файла программа предлагает команды:

```text
1. Поиск по уровню
2. Поиск по тексту
3. Поиск по дате
4. Показать статистику
5. Показать частые ошибки
6. Сохранить отчет
0. Выход
```

В командах поиска значение `0` возвращает пользователя в главное меню.

## Статистика

Программа показывает:

```text
Количество корректных строк
Количество поврежденных строк
INFO
WARNING
ERROR
```

Уровень `DEBUG` доступен для поиска, но не включён в общую статистику уровней.

## Частые ошибки

Для подсчёта одинаковых сообщений используется `collections.Counter`.

Метод `.most_common(3)` возвращает до трёх самых частых сообщений из корректных записей уровня `ERROR`.

Если записей `ERROR` нет, программа выводит соответствующее сообщение.

## Сохранение отчёта

Отчёт содержит:

* имя исходного лог-файла;
* количество корректных записей;
* количество повреждённых строк;
* статистику уровней `INFO`, `WARNING` и `ERROR`;
* до трёх самых частых сообщений уровня `ERROR` и количество их повторений.

Файл сохраняется в ту же папку, где находится выбранный лог.

К имени исходного файла добавляется окончание `_report`, а отчёт получает расширение `.txt`.

Например:

```text
application.log
application_report.txt
```

## Обработка ошибок

Программа не завершается с необработанной ошибкой при следующих ситуациях:

* путь не существует;
* вместо файла выбрана папка;
* выбран файл другого формата;
* лог нельзя прочитать как UTF-8;
* нет доступа к чтению лог-файла;
* нет доступа к записи отчёта;
* произошла другая системная ошибка чтения или сохранения;
* строка содержит неправильную или невозможную дату.

## Как запустить

Перейти в папку проекта:

```bash
cd 11_log_analyzer
```

Запустить программу:

```bash
python log_analyzer.py
```

После запуска ввести полный или относительный путь к нужному `.log`-файлу.

## Пример работы

```text
Введите путь к файлу: example.log

1. Поиск по уровню

3. Поиск по дате
4. Показать статистику

Количество поврежденных строк: 3
```

Точные значения зависят от содержимого выбранного файла.
