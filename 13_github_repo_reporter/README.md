# 13 GitHub Repo Reporter

Консольная программа для получения информации о репозитории через GitHub REST API и создания текстового отчёта на Python.

Проект сделан для закрепления работы с HTTP-запросами через библиотеку `requests`, данными в формате JSON, датой и временем, обработкой сетевых ошибок и автоматическим тестированием через `pytest`.

Пользователь вводит имя репозитория в формате `владелец/репозиторий`, после чего программа запрашивает данные у GitHub, выводит отчёт в консоль и сохраняет его в файл `repository_report.txt`.

## Формат ввода

Имя репозитория нужно вводить в формате:

```text
владелец/репозиторий
```

Пример:

```text
python/cpython
```

Программа удаляет пробелы по краям строки и проверяет:

* что ввод не пустой;
* что строка состоит ровно из двух частей;
* что между владельцем и репозиторием находится один разделитель `/`;
* что обе части заполнены;
* что внутри имени нет пробельных символов.

При ошибке программа выводит сообщение и повторяет ввод.

## Возможности

* ввод и проверка полного имени репозитория;
* отправка GET-запроса к GitHub REST API;
* ограничение времени ожидания запроса через `timeout`;
* получение ответа в формате JSON;
* формирование текстового отчёта;
* обработка отсутствующего описания;
* обработка неопределённого основного языка;
* преобразование даты последнего обновления в удобный формат;
* вывод отчёта в консоль;
* сохранение отчёта в `repository_report.txt`;
* обработка сетевых и файловых ошибок;
* автоматические тесты через `pytest`.

## Данные в отчёте

Программа показывает:

* название репозитория;
* полное имя репозитория;
* описание;
* основной язык;
* количество звёзд;
* количество форков;
* количество открытых задач;
* дату и время последнего обновления.

Дата из ответа GitHub преобразуется из формата:

```text
2026-08-01T12:30:45Z
```

в формат:

```text
01.08.2026 12:30:45
```

## Обработка ошибок

Если GitHub не ответил за установленное время, программа выводит:

```text
Превышено время ожидания
```

При другой ошибке соединения:

```text
Ошибка соединения
```

Если репозиторий не найден:

```text
Репозиторий не найден
```

Для других HTTP-ответов программа выводит полученный код ошибки.

При невозможности сохранить отчёт программа сообщает об отсутствии доступа или другой файловой ошибке.

## Пример работы

Ввод:

```text
Введите название репозитория в формате владелец/репозиторий: python/cpython
```

Пример отчёта:

```text
Название: cpython
Полное имя: python/cpython
Описание: The Python programming language
Основной язык: Python
Количество звёзд: 70000
Количество форков: 30000
Количество открытых задач: 9000
Последнее обновление: 01.08.2026 12:30:45
```

Числовые значения и дата в примере приведены только для демонстрации формата. Фактические данные зависят от состояния репозитория на момент запроса.

После выполнения программы тот же отчёт сохраняется в файл:

```text
repository_report.txt
```

## Как запустить

Перейти в папку проекта:

```bash
cd 13_github_repo_reporter
```

Установить библиотеку `requests`:

```bash
python -m pip install requests
```

Запустить программу:

```bash
python github_repo_reporter.py
```

Для выполнения запроса требуется подключение к интернету.

## Автоматические тесты

Для запуска тестов нужен `pytest`:

```bash
python -m pip install pytest
```

Запускать тесты нужно из папки проекта:

```bash
python -m pytest
```

Проект содержит 7 тестов. Они проверяют:

* формирование обычного отчёта;
* обработку отсутствующего описания и языка;
* правильность URL и значения `timeout`;
* обработку `requests.Timeout`;
* обработку `requests.RequestException`;
* нормализацию имени репозитория;
* повторный ввод после пустой строки.

В тестах используются:

* `assert`;
* собственная фикстура `@pytest.fixture`;
* встроенные фикстуры `monkeypatch` и `capsys`;
* подмена `requests.get()` без настоящего обращения к интернету;
* подмена встроенной функции `input()`;
* `iter()` и `next()` для последовательной передачи нескольких ответов.

## Статус проекта

Проект завершён как учебный мини-проект для закрепления GitHub REST API, HTTP-запросов через `requests`, обработки JSON-ответов, `datetime.strptime()`, `strftime()`, `pathlib`, сетевых исключений и тестирования внешних зависимостей через `pytest` и `monkeypatch`.
