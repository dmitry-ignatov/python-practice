# 15 Task API

Учебный REST API для управления задачами на FastAPI.

Проект сделан для перехода от использования чужих REST API через `requests` к созданию собственного HTTP API. Здесь закрепляются маршруты FastAPI, HTTP-методы, path parameters, Pydantic-модели, коды ответа, обработка ошибок и тестирование API через `TestClient` и `pytest`.

Данные пока не сохраняются в базу: задачи хранятся в обычном Python-списке в оперативной памяти. Это позволяет сосредоточиться именно на устройстве API. После перезапуска приложения список возвращается к исходному состоянию.

## Возможности

API позволяет:

* получить информацию о корневом endpoint;
* получить список всех задач;
* получить задачу по её `id`;
* создать новую задачу;
* изменить название существующей задачи;
* удалить задачу;
* вернуть `404 Not Found`, если запрошенной задачи нет;
* автоматически проверять основное поведение API через `pytest` и `TestClient`.

## Endpoints

### `GET /`

Возвращает:

```json
{
  "message": "Task API"
}
```

### `GET /tasks`

Возвращает список всех задач.

Пример:

```json
[
  {
    "id": 1,
    "title": "Купить хлеб"
  },
  {
    "id": 2,
    "title": "Выучить FastAPI"
  }
]
```

### `GET /tasks/{task_id}`

Возвращает одну задачу по её `id`.

Если задачи нет, API отвечает кодом `404`:

```json
{
  "detail": "Task not found"
}
```

### `POST /tasks`

Создаёт новую задачу.

Тело запроса:

```json
{
  "title": "Новая задача"
}
```

Пример ответа:

```json
{
  "id": 3,
  "title": "Новая задача"
}
```

При успешном создании используется статус `201 Created`.

### `PATCH /tasks/{task_id}`

Изменяет название существующей задачи.

Тело запроса:

```json
{
  "title": "Новое название"
}
```

Если задача не найдена, API отвечает `404 Not Found`.

### `DELETE /tasks/{task_id}`

Удаляет задачу и возвращает удалённый объект.

Если задача не найдена, API отвечает `404 Not Found`.

## Pydantic-модели

Для тела запросов используются модели:

```python
class TaskCreate(BaseModel):
    title: str


class TaskUpdate(BaseModel):
    title: str
```

FastAPI использует их для чтения и проверки JSON-тела запроса перед вызовом обработчика endpoint.

## Хранение данных

В проекте пока используется список:

```python
tasks = [
    {"id": 1, "title": "Купить хлеб"},
    {"id": 2, "title": "Выучить FastAPI"}
]
```

Он существует только в памяти запущенного Python-процесса. База данных будет добавлена на следующем этапе обучения.

## Как запустить

Перейти в папку проекта:

```bash
cd 15_task_api
```

Установить FastAPI со стандартными зависимостями:

```bash
python -m pip install "fastapi[standard]"
```

Запустить сервер разработки:

```bash
python -m fastapi dev task_api.py
```

После запуска API доступен по адресу `http://127.0.0.1:8000`, а автоматическая документация Swagger — по адресу `http://127.0.0.1:8000/docs`.

## Автоматические тесты

Для запуска тестов нужен `pytest`:

```bash
python -m pip install pytest
```

Запускать тесты нужно из папки проекта:

```bash
python -m pytest -v
```

Проект содержит 9 тестов. Они проверяют:

* корневой endpoint `GET /`;
* получение списка задач через `GET /tasks`;
* получение существующей задачи;
* `404` при запросе отсутствующей задачи;
* создание задачи через `POST /tasks` и статус `201`;
* изменение существующей задачи через `PATCH`;
* `404` при попытке изменить отсутствующую задачу;
* удаление существующей задачи через `DELETE`;
* `404` при попытке удалить отсутствующую задачу.

В тестах используются:

* `fastapi.testclient.TestClient`;
* `pytest`;
* `assert`;
* собственная fixture с `autouse=True`;
* сброс `task_api.tasks` перед каждым тестом для изоляции состояния;
* отправка тестовых `GET`, `POST`, `PATCH` и `DELETE` запросов без запуска отдельного сетевого сервера.
